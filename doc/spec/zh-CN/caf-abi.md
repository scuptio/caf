# CAF 规范值编码(`caf-abi`)—— v1

> [English](../en/caf-abi.md) | 简体中文

状态:草案(**不稳定**) · 适用于容器格式 v1(核心模块执行)。

容器规范([`container-format.md`](container-format.md))规定字节如何布局与
校验;本文档规定在组件模型规范 ABI 尚未启用时,**值**如何跨越宿主↔组件边
界。它把过去的临时约定变成宿主与组件作者都可以依赖的契约。

## 1. 执行模型

格式 v1 针对 `caf.*` 宿主 ABI 执行**核心 WASM 模块**。WIT 是*声明的*契约,
调用针对原始 WASM 导出进行。构建时,声明能力的每个函数都必须具有参数与结
果类型与 caf-abi 完全一致的真实函数导出。缺失导出、种类/类型错误、模块畸
形或内存桥不合法都是硬错误。kebab-case 的 WIT 名字可以绑定到 snake_case 的
WASM 名字;归一化后有歧义的名字被拒绝,清单记录实际的 WASM 导出名。未绑定
到组件能力的 world 导出不予公布。每个构件级能力必须有实现它的组件。真正的
组件模型实例化是 v2 升级路径(见 §6)。

## 2. 标量

- WIT 标量类型直接映射:`u32/s32` → `i32`,`u64/s64` → `i64`,
  `f32`/`f64` → `f32`/`f64`,`bool` → `i32`(0/1),`char` → `i32`(标量
  值)。
- 枚举和至多 32 个标志的 flags 下沉为 `i32`;更大的标志集使用复杂值编码。
  类型别名按其目标类型下沉。
- WIT 签名只含标量的函数不需要内存桥。

## 3. 复杂值

复杂值(string、list、record、option、result、bytes)被**编码为字节**,
放入组件的线性内存,以 `(ptr, len)` 引用。

- **默认编码:规范 CBOR** ——与清单相同的规范形式(定长、最短形式整数、
  字典序映射键)。宿主本就为清单携带 CBOR 解码器;组件得到的是机器友好、
  自描述的格式。
- **profile 可以选择不同的编码**(例如 GIS 演示 profile 用 UTF-8 JSON 以
  便人工查看结果)。编码是 *profile 约定*,记录在 profile 文档中;下述传输
  机制是固定的。

### 3.1 参数

对于复杂参数,宿主:
1. 调用组件导出的 `alloc(len: u32) -> u32`,
2. 把编码字节写到返回的指针处,
3. 以 `(ptr: i32, len: i32)` 代替该值调用函数。

### 3.2 结果

返回复杂值的函数返回单个 `i64`:

```text
result = ptr | (len << 32)
```

- 客端分配缓冲区并**把它泄漏给宿主**;宿主读取 `ptr` 处的 `len` 字节,然
  后调用组件导出的 `dealloc(ptr: u32, len: u32)` 释放它。
- 绑定函数接受或返回复杂值的组件**必须**导出 `alloc: (i32) -> i32`、
  `dealloc: (i32, i32) -> ()`,以及名为 `memory` 的非共享 32 位线性内存。
  仅有导出名不满足桥的要求:构建器会验证它们的种类与签名。
- `len == 0` 且 `ptr == 0` 编码空值。
- 复杂结果始终使用 `i64`;`i32` 结果是标量,不是打包的指针/长度对。

### 3.3 emit 通道

对于大于实际内存拷贝开销的输出或真正的流式结果,组件使用
`caf.emit(ptr, len)`:块被追加到宿主的 emit 缓冲区并计入 `output_max`。
profile 定义发出的块如何为单个值分帧(推荐换行分隔的 CBOR/JSON)。

## 4. 参考实现

- 客端(Rust):`caf-guest` crate 提供 `alloc`/`dealloc`、
  `return_bytes`/`return_str`/`return_json`,以及 payload-fs 导入的安全封
  装。
- 宿主端(原生):`caf-runtime` 中的 `Session::call` +
  `Session::read_memory`;打包结果用 `is_packed_result` 检测。
- 宿主端(浏览器):`caf.js` 实现相同的打包规则。

## 5. 错误

失败的能力调用返回 profile 错误形状的编码(例如 `{ "error": "message" }`),
绝不产生陷阱(trap)。陷阱保留给预算耗尽和策略违规——它们由宿主执行,不
是值。

## 6. 到组件模型的升级路径(v2)

v2 构件可以携带真正的组件(内嵌 world 元数据,构建时已通过 `embed = true`
支持)。v2 运行时通过组件模型规范 ABI 实例化它们,WIT 类型原生下沉/提升,
本文档 §3 不再适用。不能运行组件的宿主(例如没有转译胶水层的浏览器)继续
接受 v1 构件;容器格式通过未来的 `format_version` 升级来表明构件需要哪种执
行模型。鼓励 profile 保持其 WIT 事实来源稳定,使同一接口在两种 ABI 下都能
工作。
